# Decisions and deviations

One line per decision: date · decision · reason · alternatives rejected.

- 2026-09-27 · Support Node `>=22.18` (engines) and verify on Node 24.21 LTS as well; `.nvmrc` stays `24` · The host PC has Node 22.18.0, which already runs TypeScript natively (type stripping unflagged since 22.18.0); the spec's `>=24.11` would make `pnpm install` warn on the machine that actually runs the table. Tests run on both 22.18 (host) and a portable 24.21 (spec target). `@types/node@22` keeps the type checker honest about APIs that don't exist on 22 · Rejected: upgrading the host's system Node in place (changes the machine outside the repo); `>=24.11` (false claim of incompatibility).
- 2026-09-27 · pnpm 12.6.0 under corepack: Node 22.18 bundles corepack 0.33, which leaves a broken cache for pnpm 12 (native-exe layout) and fails with `Cannot find module …pnpm.cjs`. Fix: run `npx corepack@latest pnpm --version` once (or `npm i -g corepack@latest`); Node 24.21 bundles corepack 0.36, which works. Documented in HOSTING.md · Rejected: downgrading to pnpm 11 (spec pins 12 and its `allowBuilds` config).
- 2026-09-27 · react-router pinned to 7.18.4 · Spec says "latest 7.x"; 8.4.0 is now latest, but 7.x is what the spec asks for.
- 2026-09-27 · `pnpm start`/`pnpm dev` pass `--production`/`--dev` to `packages/server/src/main.ts`, which sets `NODE_ENV` before importing the server · `NODE_ENV=production node …` in a package script doesn't work under cmd.exe on Windows; an entry file is cross-platform without adding `cross-env`.
- 2026-09-27 · Type-checking uses `tsc -b` with composite projects that emit declarations only into `node_modules/.cache/tsc` · TS build mode requires composite projects to emit; the cache dir is gitignored and nothing ships from it.
- 2026-09-27 · Stop hook runs `pnpm --silent check:fast` instead of `pnpm -s check:fast` · pnpm 12's rewritten CLI rejects `-s` ("unexpected argument"); `--silent` works. Library wins for API details (§4.1).
- 2026-09-27 · Spike code lived in `packages/{server,web}/spikes/` rather than a root `spikes/` folder · Inside the packages it resolves their installed dependencies without adding a throwaway workspace package (which would have churned the lockfile while research agents were using node_modules). Deleted at the end of Phase 0 as §32 requires.
- 2026-09-27 · Extra schema beyond §12.2: `table_sessions` (one row per opening of the table: crash hygiene, "session ended unexpectedly", log grouping), `devices.banned_at` (ban covers devices), `sessions.device_id/identity_kind/device_label/knocked_at/admitted_as` (knock cards, auto-admit, rejoin), `users.deleted_at`, `scenes.deleted_at/data_json`, `actors.status_json/deleted_at`, `assets.purpose`, `handouts.kind` (handout vs secret note), `history.table_session_no`, `*.data_json` catch-alls · All needed by specified behaviour; none change §12.2 semantics.
- 2026-09-27 · Data-directory permissions on Windows use `icacls <path> /inheritance:r /grant:r <user>:F` (fixed args, no shell) · Windows has no POSIX mode bits; ACLs are how Windows "supports" owner-only permissions (AC-SEC-08). POSIX uses 0700/0600.
- 2026-09-27 · Client IP for rate limits and logs is computed by Gloam (`cf-connecting-ip` only when the socket peer is loopback, else the socket address) and never taken from Colyseus's `AuthContext.ip` · Colyseus derives `ip` from proxy headers, which a LAN client could forge (AC-AUTH-01).
- 2026-09-27 · Rules corrections from R1 (docs/research/rules-5.2.1.md), applied in the rules engine and content: Shining Smite requires Concentration (1 min) and grants Advantage on attacks against the target; Conjure Celestial p. 118 (up to 10 min); revival rules p. 180; Short Rest p. 187, Long Rest p. 185; Grappled escape DC 8+Str+PB applies to Unarmed Strike grapples only (monsters use their stat-block DC); Incendiary Cloud drifts away from the caster; Insect Plague is also Difficult Terrain; Flaming Sphere is 5 ft in diameter; Incapacitated can't speak (no Verbal spells); Petrified is immune to Poisoned; a Short Rest restores at least 1 HP per Hit Die spent; a Long Rest also restores lowered ability scores; Truesight also auto-succeeds on saves against visual illusions; SRD 5.1 concentration DC has no 30 cap.
- 2026-09-27 · "Two sizes larger or smaller" (SRD p. 14, moving through creatures) is implemented as "two or more sizes different" · A creature three sizes larger is at least as easy to pass as one two sizes larger; the spec already reads it this way. Rejected: exactly two.
- 2026-09-27 · Speed 0 can't be increased: when a speed-zero condition applies (and `ignoreConditionSpeed` is off) the whole turn budget is 0, including DM bonus movement · SRD: a Speed of 0 can't increase; §19.4's formula would otherwise add `bonusMove` to 0. The DM can still override via "ignore condition speed effects" or a DM move (P2).
- 2026-09-27 · Advantage/disadvantage from multiple conditions is combined (any adv + any dis → normal), never overridden by one condition (e.g. Unconscious+Prone attacked from beyond 5 ft) · SRD p. 8 rule on advantage and disadvantage; R1 flagged it as an engine trap.
- 2026-09-27 · The whole campaign (all scenes' walls/lights/zones/tokens/effects, actors, combat) is loaded into the server's in-memory model when the table room is created, rather than loading prep scenes on demand (§13.7) · Campaigns are small (tens of scenes, low thousands of entities); one model makes prep view, snapshots, undo and restore uniform. Prep scenes still never reach players: only the DMs subscribed via `prep.open` receive `prep.patch`.
- 2026-09-27 · `move.preview` sent by a DM (or Admin) is relayed only to other DMs; players see DM-moved tokens only when the move commits (R5 trap: the DM's drag previews leak intent) · Player previews still go to everyone who can see the token (AC-MOV-13).
- 2026-09-27 · `roll.masked` carries only `{ id, rollerId, rollerName, visibility, dieCount }` — no formula, label, dice or purpose — and plays a fixed "?" throw (R5 trap: masked rolls must not leak "8d6" or "Insight").
- 2026-09-27 · Token `reachFt` is a public token field (players need hostile reach to draw opportunity-attack warnings; reach is visible at a real table).
- 2026-09-27 · Emotes are delivered per viewer: a viewer who can't perceive the sender's token gets the emote anchored to the sender's portrait instead (R5 trap: an emote bubble must not reveal a token in the dark).
- 2026-09-27 · Fog feathering is applied inside the visibility polygon only (the soft edge never extends past a sight-blocking wall) (R5 trap: feathered edges leaking light through walls).
- 2026-09-27 · "Share my rulers" defaults off for DMs (on for players, per §8.6); the resolution card never shows players a hit chance derived from hidden AC.
- 2026-09-27 · Torch/candle flicker amplitude and VFX flashes are capped below 3 luminance flashes per second (WCAG 2.3.1) and disabled entirely under reduced motion.
- 2026-09-27 · Ctrl+wheel is treated as zoom (trackpad pinch arrives as Ctrl+wheel); template rotation uses `[`/`]` or plain wheel while placing (§8.13), never Ctrl+wheel.
- 2026-09-27 · Ambient shader backdrops (`ShaderCanvas`) render in a module worker on an OffscreenCanvas (main-thread fallback where unsupported), start after the first paint and fade in on their first frame · Evidence: under software GL (SwiftShader, as on machines without GPU acceleration) context creation, `getProgramParameter` and especially `loseContext()` blocked the page for up to 2.3 s per screen change (CDP profile); with the worker the waiting room appears in ~130–380 ms with zero long tasks. WebGL 1, not 2: context creation costs ~75 ms vs ~310 ms on software GL. Main-thread fallback releases its context 1 s after its loop stops (measured drain ≈ 600 ms; release then costs ~3 ms).
- 2026-09-27 · The panel grain is a committed 128×128 PNG (`tools/gen-noise-texture.mjs`, seeded, dependency-free encoder), not generated at startup · `toDataURL()` on a GPU-backed canvas is a synchronous readback: 1.4 s long task on every page load under software GL.
- 2026-09-27 · The web client sets `z.config({ jitless: true })` · zod 4 probes for eval with `new Function("")` on first object parse; our CSP forbids eval, so every page emitted a CSP violation report. Adding 'unsafe-eval' is not an option.
- 2026-09-27 · E2E guard: CSP reports received by the server are forwarded to the test runner over IPC (test mode only) and fail the test, as do console errors and uncaught page exceptions; browser contexts opened in a test are closed before its server stops · The console-text check alone missed eval violations ("Refused to evaluate…"). This caught the zod probe and a double `room.leave()` on closed sockets (fixed with `leaveRoom()`).
- 2026-09-27 · Playwright runs with the real autoplay policy (no `--autoplay-policy=no-user-gesture-required`) · With the flag every AudioContext starts unlocked, so "the knock sound played" and the locked-audio chip (AC-AUD-04) would be untestable.
- 2026-09-27 · Latency ACs (AUTH-02/03, and later ones) are measured in-page: a MutationObserver installed before the action records `Date.now()` when the target heading is laid out; the clock starts when Playwright's action is delivered · Playwright's retrying assertions poll on a 0/100/250/500 ms back-off (up to +500 ms error) and its actionability wait on an animating toast is harness time, not product latency. The observer surviving the transition also proves "no reload".
- 2026-09-27 · Admission: the table connection starts as soon as `/api/join/enter` confirms (inside the 450 ms dissolve) and the table screen appears when joined + welcomed (bounded at 4 s). `net/table.ts` owns one idempotent connection per campaign and forwards one-shot messages through a replaying event bus, so events sent during the hand-off (welcome, knocks, kicked) are never dropped · Measured admit → table 513 ms (AC-AUTH-03 ≤ 1 s).
- 2026-09-27 · Tag revocation in per-client views uses `view.remove(item, TAG)` (sends the client DELETEs for exactly the tagged fields) followed by `view.markVisible(item[$changes])` · @colyseus/schema 5.0.34's `remove(item, tag)` also clears the item's own visibility bit, after which the client silently stops receiving every update to that item (found by board.test: a token switched Exact→Bar froze for the player). A same-patch remove + re-add doesn't work either — the encoder coalesces it into an ADD and the stale field survives. Regression-tested.
- 2026-09-27 · `token.update` uses dedicated patch schemas (`AppearancePatch`, `TokenStatsPatch`) with no defaults, merged field by field (speeds/senses/saves deeply; `null` clears optional appearance fields) · zod 4 applies `.default()` inside `.partial()`, so `{ appearance: { mode: "coin" } }` reset scale/offset and `{ stats: { hp } }` would have reset speeds and senses. `stats.size` is optional; the token's `size` is the single source.
- 2026-09-27 · HP per display mode for non-controllers: Exact → numbers (TAG_HP) + fraction + band; Bar → fraction + band; Descriptor → band only (`hpFrac` −1); Hidden → nothing (`hpBand` 255). Controllers and DMs always hold TAG_HP · The fraction alone would leak more than a descriptor shows.
- 2026-09-27 · DM-hidden (`hidden: true`) wins over ownership and `revealTo`: no player receives a hidden token, not even its owner (AC-TOK-08 "never present in any player's state").
- 2026-09-27 · Prep view (§13.7): the whole campaign is already in memory, so `prep.open` only subscribes the DM connection and returns a snapshot in the same view shapes as the live state; commits touching a non-active scene become `prep.patch` messages (re-projected upserts + removed ids), never state changes. Players' sockets are asserted (raw frames) to receive nothing from a prep scene.
- 2026-09-27 · Recalibrating an image map scales positions of walls, zones, lights (carried ones too) and effect anchors, and the scene bounds/spawn; token sizes, light radii and area sizes stay (they are rules distances in feet, not map art).
- 2026-09-27 · Polyglot policy: images are refused when they contain active content anywhere (`<script`, `<html`, `<svg`, `<?php`, `javascript:` …) or when an archive/document/program/markup starts right after the image's end marker (parsed per format: PNG IEND, JPEG EOI after the scans, GIF trailer, RIFF size, ISOBMFF boxes); other trailing bytes are dropped by re-encoding · Rejecting all trailing data would refuse phone "motion photos" (an MP4 after the JPEG); short binary signatures are only checked at the end marker because a 4-byte ZIP signature would match by chance in ~0.6 % of 25 MB files.
- 2026-09-27 · GLB minis over 300 primitives (maps: 5 000) are refused with "join the parts (Ctrl+J)" advice; simplification escalates its error tolerance 0.01 → 0.05 → 0.1 and refuses a model still above 1.5× its triangle budget · Simplification is per primitive, so thousands of tiny parts can't be reduced, and each part is a draw call for every player. The spec's budget is "toward"; shipping 10× over it would break frame rates.
- 2026-09-27 · Upload aborts answer immediately and then drain (discard) the rest of the body, without `Connection: close`, cut off after 30 s (nginx's lingering_time) · Closing a socket with unread input sends a TCP RST and the client's stack discards the 413 it already received (verified: ECONNRESET, no answer). Nothing past the cap is stored.
- 2026-09-27 · The asset processor child gets a minimal environment (PATH, SystemRoot, NODE_ENV) and writes only into a per-job staging directory the parent creates; the parent moves outputs into content-addressed storage (`assets/<sha[0:2]>/<sha>-<profile>-<variant>`). A job is bound to the child it ran on, so a killed child's late exit/RSS events can't fail or kill the next job (a race found by the hang→oom test).
- 2026-09-27 · Asset references are an entity kind in the campaign model: Library rename/tags/overrides/delete/restore are undoable commands; `asset.review` (approve/reject) and the internal `asset.register` (uploads) are recorded but not undoable (AC-UNDO-05). `CommandDef.internal` keeps server-only commands off the room's message list.
- 2026-09-27 · File-level de-duplication keys on (SHA-256, output profile), since the same bytes produce different variants as a map vs a token; approval stays per reference. Quota counts each distinct file once per uploader (pending + approved, not deleted).
- 2026-09-27 · Test-only knobs: processor timeouts/RSS ceiling via `config.processor` and content-marked hook files (`__gloam_test_hang|oom|crash__`, honoured only with GLOAM_TEST_PROCESSOR_HOOKS=1, set only when NODE_ENV=test); a test asserts the production constants equal the spec's.
- 2026-09-27 · `pnpm dev` uses `node --watch-path=packages/server/src --watch-path=packages/shared/src` instead of `--watch` · `--watch` follows every imported module, and the Vite dev middleware imports temporary files it writes (bundled config, dep-optimizer output), so each start triggered a restart forever. Web changes are covered by Vite HMR. Setup/magic tokens stay in memory by design, so a server restart issues a fresh link (the newest is always the last `token=` line of the dev log).
- 2026-09-27 · Scene travel holds the old scene on the board (`entities.held`) while the screen fades to black, swaps under the black, waits for the new scene's assets (min 550 ms for the name, max 8 s), then fades in; the HUD stays visible and usable · Switching data first and fading after would show the new scene popping in before the fade (a visible jump, AC-BRD-05). A DM preparing another scene is not moved. Transitions arm only after the first-load intro, which covers the first scene.
- 2026-09-27 · The first-load intro holds on the lit candle until the board has drawn its first frame and its assets have loaded (never less than the 400 ms ignition, at most 6 s), then fades up over 900 ms; HUD groups carry `data-hud-order` and rise in 60 ms apart using opacity/transform only (no layout change). Any key or click skips with a 150 ms fade. Once per page load.
- 2026-09-27 · Settings popover (P2) shows the settings that act today — volumes per channel, graphics tier pin, UI size, motion, colour-blind palette, "Let the DM move my camera" (players only). "Focus camera on my turn", "Share my rulers", dice animation and the units override join it in the phases that give them an effect (P8, P3, P5, P3) · A switch that changes nothing is a dead control.
- 2026-09-27 · The radial menu's P2 slices are Elevation (±5 ft), Facing (±45°), Look (model/standee/coin/auto), and for DMs Hide/Reveal, Lock, Duplicate, Delete (with Undo). Sheet, Conditions, Damage/Heal, Light, Target and Emote arrive with their phases (P6, P7, P7, P4, P9, P11).
- 2026-09-27 · Library drops: art and minis become unlinked tokens at the drop point (mode model for GLBs, auto for images, schema-default disposition hostile); a map opens the New scene wizard with it; audio and handouts are refused with a toast.
- 2026-09-27 · Ambient shaders (join/waiting-room candles, intro candle, floor picker) share ONE worker and ONE WebGL context (OffscreenCanvas) for the page's lifetime; frames reach `bitmaprenderer` canvases as transferable ImageBitmaps; programs are compiled once per shader and kept · Measured under software GL: releasing a context (even inside a worker) froze every other context — the board included — for ~2.5 s, e.g. right after the intro or on arriving from the waiting room. Keeping per-screen contexts alive instead would pile up until Chrome evicts the oldest (possibly the board's). The on-page fallback (no worker WebGL) keeps its own context.
- 2026-09-27 · The intro overlay covers at 99.5 % opacity and the board counts as ready only after its first frame, with assets loaded, and 300 ms of frames under 100 ms · Fully opaque, the compositor culled the board canvas, so its first composite (a multi-second stall on software GL) landed mid-fade; a couple of quick frames weren't proof either (a second warm-up stall followed ~0.2–0.9 s after the first frame). Now the warm-up happens behind the candle (capped at 6 s) and the fade itself runs at a steady frame rate.
- 2026-09-27 · Generate walls unions the sliced solids itself (non-zero fill on a ≤ 0.1 ft raster, outline traced on cell edges, RDP 0.25 ft) rather than depending on a polygon library · The only maintained pure-JS Clipper2 port (`clipper2-js`) is packaged as an Angular library and pulled Angular 15, rxjs and zone.js into the install via auto-installed peers. Lattice-aligned walls come out exact; other edges within ~0.07 ft, inside the spec's tolerance. Consecutive batches share an `undoGroup` (a command-bus envelope field like `cid`) so one Ctrl+Z removes a whole generated set; a grouped undo is checked as a whole before anything changes.
- 2026-09-27 · The board renders on demand (R3F `frameloop="demand"`): store changes, board input and finished loads wake it for 1 s; camera tweens/follow, token glides and crossfades, the HP ghost request frames while they run; the selection pulse and idle mini animations register as animating; the tier governor only measures back-to-back frames (a gap > 200 ms is idleness, not slowness) · Measured: two idle boards redrawing at 60 fps starved each other to 2–3 fps under software GL, and an idle table on the host PC (which also runs the server), a laptop or a phone should cost nothing.
- 2026-09-27 · Mouse/pen panning is "grab the table": the table point under the pointer at press stays under it (camera and target translate by grab − current ground point) — left-drag on empty table, middle-drag, Space+drag with any tool (over tokens too), the Pan tool · camera-controls' SCREEN_PAN scales vertical drags by the target distance, so at 55° pitch the grabbed point slid ~7 % behind the pointer. One-finger touch panning stays with camera-controls until the P14 gesture pass (it must share the pointer with pinch/rotate).
- 2026-09-27 · Camera timing in E2E is measured from rendered frames against the rig's recorded tween start (each mid-flight frame implies a duration through the inverted easing; ≥ 3 frames aggregated over repeated transitions), at an 800 × 500 board · Software GL renders the PBR table and procedural floors at a few frames per second, so "when did it stop" sampling was off by up to a frame. Follow-up for P15 (PERF): a software-GL render profile (render scale < 1, cheaper table/floor materials) for players whose GPU is blocklisted.
- 2026-09-27 · The E2E `admin` fixture now takes the configured/`test.use` viewport (a hand-made context silently got Playwright's 1280 × 720 instead of the configured 1440 × 900).
- 2026-09-27 · Dust motes (SPEC §8.4 table environment): one additive Points draw, brightest inside a shaft along the key light, counts per tier (Low 0 / Medium 60 / High 110 / Ultra 160), drifting on rendered time; as ambient motion they get at most 30 paced frames a second when nothing else is drawing, those paced frames are excluded from the tier governor, and reduced motion holds them still.
- 2026-09-27 · The tier governor measures a frame only when the previous frame asked for it straight away (a continuous run), however long it took; its 3 s / 10 s / first-second windows run on real elapsed time, and the test hook's forced frame time replaces only the measured frame duration · An idle-gap threshold would have hidden a genuinely slow device (a 4 fps board would never step down); forced time advancing the clock made the 10 s window take 2 000 frames.
- 2026-09-27 · A code chunk that fails to load (`vite:preloadError`) reloads the page once (guarded for a minute in sessionStorage); a repeat goes to the error boundary · Browsers keep a failed dynamic import failed for the page's life, so one dropped fetch over the tunnel would strand a player on a broken screen. Found when a P1 journey's Join chunk fetch failed while another test's server decoded a 16 384² map.
- 2026-09-27 · Scene travel is a freeze-frame: just before the live scene switches (synchronously, in the store update) the board renders one frame through its full pipeline and copies it into a still that covers the canvas; the board switches underneath at once, so the new scene's warm-up overlaps the fade-out; the still fades to black, the name shows (≥ 550 ms), and the new scene fades in once it has drawn 2 frames and its assets are in (≤ 8 s). Replaces holding the old scene's data (`held`), under which the new scene only began rendering once the screen was already black.
- 2026-09-27 · Outgoing board materials are disposed 5 s late (`disposeLater`) · three.js frees a shader program the moment no material uses it, so a scene change freed and recompiled the same programs (floor, table, tokens, overlays) — measured 24 → 18 programs and a ~0.9 s first frame under software GL; now 24 → 24 and travel completes in 1.5–1.9 s.
- 2026-09-27 · Timing journeys (`@timing`: ≤ 1 s admissions, 400/600 ms camera tweens, the intro timeline, 2 s scene travel) run in their own Playwright project with one worker, after the parallel journeys; `pnpm test:e2e` runs both parts and fails if either fails (no project `dependencies`, which would silently skip the timing part when an unrelated test fails) · Under software GL all workers share the CPU; a neighbour decoding a 16 384² map was being measured instead of the app.
- 2026-09-27 · Code-split screens and panels use `lazyPage()`: an import cancelled for the chunk-failure reload stays pending (Suspense fallback) instead of throwing "Cannot read … default" in the moment before the reload.
- 2026-09-27 · Asset privacy: players get a render-only view of assets (`GET /api/assets/:id` and pushed `asset.render`: class, size, colour, variants, mini bounds/animations, overrides) — never name, tags or uploader; DMs and the uploader get the full record; a player's Library lists only their own uploads · Players learn asset ids from the tokens they see, and a DM's "Boss form (act 3)" upload would otherwise spoil itself. Render views go out only when they change (a rename sends nothing).
- 2026-09-27 · Per-asset mini overrides (scale, turn, lift) apply to every token using the mini, multiplied/added with the token's own appearance values; they previously weren't applied at all.
- 2026-09-27 · GLB textures load through an image element (GLTFLoader plugin swapping in TextureLoader) · three.js's ImageBitmapLoader fetch()es the blob: URL of each embedded image, which the spec's `connect-src 'self'` (never relaxed) forbids.
- 2026-09-27 · Dialogs never exceed the viewport: title and buttons stay, the body scrolls (the Quick Unit dialog's button was unreachable on a 600-px-tall screen). The first frame after an idle pause animates with a nominal 1/60 s (a board-level frame delta), so token glides and the auto crossfade don't jump when the table wakes.
- 2026-09-27 · Token overlays declutter in screen space: each rendered frame, overlays are placed by priority (hovered > selected > the viewer's own > party > others, nearer first) and one that would overlap an already placed overlay fades out (150 ms); HP numbers sit inside a taller bar, so an overlay is never wider than its name or bar · Numbers beside the bar ran into the neighbouring token's plate (reported from screenshots).
- 2026-09-27 · "Was this press on a token?" is decided by the token claiming the pointer in its own press handler (boardApi.claimedPointer, consumed by the board's handler for that press), not by the hover state · A quick move-and-click beat the hover update: the board then treated the press as empty table, started a pan and cleared the selection the token had just set.
- 2026-09-27 · The UI store's debounced sessionStorage save writes the store's state when the timer fires · It captured the state of the first call in the window, silently dropping a selection or camera made within 250 ms of a hover change.
- 2026-09-27 · Map-tool field edits build on a local draft until the server echoes them · Committing X, Z and Turn in quick succession sent each on top of the last confirmed transform, undoing the earlier edits.
- 2026-09-27 · DS-01 lint extended (tools/tokens-lib.mjs, unit-tested): radii only from the radius tokens, no raw type sizes, no raw durations, spacing on the 4-px grid; UI motion uses the duration tokens (scene travel: out --dur-panel, in --dur-scene; reduced motion --dur-fast; HUD rise --dur-base). The intro's 400/900/60 ms are the spec's own values.
- 2026-09-27 · Screens: the invite-code cells share the card's width (they overflowed the Join card); the admin sidebar is screen-high and sticky with its actions always reachable, and on phones "Go to the table" / "Sign out" live in the header (they were unreachable); the settings popover aligns to the screen edge over the dock; the calibration image is centred with a readable ruler; the radial ring grows with its slice count; a duplicate upload says where the existing item is.
- 2026-09-27 · `pnpm shots` = a Playwright spec (e2e/shots) rendering the P1/P2 screens at 1440×900, 1024×768 and 390×844 into artifacts/screens/p2/<viewport>/ with the journeys' guards; a step that fails is noted in _notes.txt instead of stopping the run.
- 2026-09-27 · Fades and animations step toward their target and stop there (`approach`) · The clutter fade and the auto-mode crossfade stepped *down* whenever they sat exactly at their target, so every redraw dipped settled name plates and coins toward invisible (a flicker on every camera move; screenshots caught plates half-faded). An animation that needs the next frame calls `again()`, which also marks that frame as part of a continuous run (real frame time, measured by the tier governor) — a bare invalidate() stepped 1/60 s per frame and stretched a 150 ms fade to seconds on a slow device.
- 2026-09-27 · Name plates sit a fixed on-screen gap above the token's highest point, found in screen space: the base and coin rims (sampled), the standee card's corners and the mini's bounds are projected through their real transforms (facing, overrides, lying down) and the plate is unprojected just above the highest one, at the depth of the token's top · Lifting by the base radius along the camera's up vector floated a Large mini's plate far above its head, onto the token behind it (reported); comparing heights along the up vector is only exact for orthographic views. Tokens move before overlays in each frame (frame priority), overlays read fresh matrices, and a plate still moving asks for one more frame, so an idle board never shows a one-frame-stale layout.
- 2026-09-27 · Prone/dead: a mini tips 80° onto its side *centred on its base* (it pivoted at its feet and lay beside its space); a standee lies flat, face up, centred and no longer than the base is wide, its top along the camera's screen-up (the old Euler order tipped it about the world x-axis after the camera-facing turn, so from east or west it stayed upright).
- 2026-09-27 · The GLB pipeline repairs inside-out minis (`orientShells`, after simplify): per closed, manifold, orientable shell, inconsistent winding is made consistent and outward; consistent shells are turned outward only when every closed shell in the model faces inward (a whole-model export fault); a model mixing inward and outward shells keeps them (an inverted-hull outline is deliberate); open/non-manifold surfaces are left alone; stored normals and tangents follow when they matched the old winding · Inward-wound minis (common after STL conversion) render with their near faces culled and the inside showing — the glitched "Stone Guardian" in the screenshots came from an inside-out test box. Maps are not repaired (inward rooms are a cut-away technique).

- 2026-09-28 · Visibility polygons (§15.2): the blocking segments are prepared once per wall set (`SegmentSet`). Then along any ray the segments' order is the same all through an angular interval between endpoints, and the sweep finds the nearest segment once per interval (at its middle ray) and emits it clipped to the interval's rays — exact endpoints where they are endpoints, so T-junctions can't leak. The property test (2 000 seeded scenes × 500 points) compares against a brute-force ray caster. It skips points within 0.01 ft of the *true* boundary, taken from the inputs (walls, the bound, shadow rays out of wall endpoints) rather than from the result. - 2026-09-28 · Locks and proposals (§8.10): a player's edit that touches a locked field is refused whole (`LOCKED_SHEET`, with each locked field's path, value and proposed value, for the "Propose change" button). A proposal stores the changes as proposed; the DM's card shows what approving would change on the sheet as it is then (and when it no longer fits); approval is an ordinary, undoable sheet edit by the DM. At most 20 unanswered proposals per player per sheet. Players create only their own characters, delete only their own unlocked ones (their linked tokens go with them; DMs delete any); DMs set locks and owners. New sheets start at the campaign's `sheetLockDefault` house rule.
- 2026-09-28 · Templates save a sheet's custom-block layout: kinds, titles and shape kept (a table's columns and rows, checklist items, list keys, a counter's maximum); what was filled in cleared (numbers 0, counters full, checklists unticked, list values empty); new characters get the blocks with new ids. Their maker or a DM deletes them.
- 2026-09-28 · The party (AC-SCN-06): characters of players at the table without a token on the active scene are placed round its spawn point — when the player is admitted, when a scene becomes active, when a character is made for someone at the table — by the server's own `party.place` (not undoable; a DM removes a token as any other). Spiral of 5-ft steps nearest first; a spot must fit the scene, overlap no token and no movement-blocking wall, and be reachable from the spawn in a straight line (not through a wall into the next room; an open door is no wall) — `movement/spawn.ts`, tested.
